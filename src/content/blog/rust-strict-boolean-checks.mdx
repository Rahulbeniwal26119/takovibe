# Why Rust Won’t Let You Use Numbers in `if` Statements

Hi Everyone, 👋

I’ve been grinding Rust for some time now, and one thing that surprised me early on was how **strict** Rust is about `if` conditions. Unlike C or C++, you **can’t** pass an integer or reference and expect it to be treated as `true`/`false`. Rust *complains* — on purpose.

At first, this felt annoying. But digging into *why* Rust enforces strict boolean checks made me appreciate the design: it prevents hidden bugs, preserves type safety, and improves readability.

## 🚫 No Implicit “Truthiness”

If you’re coming from C/C++, this will look familiar:

```c
int x = 5;
if (x) {                // non-zero is truthy
    printf("x is non-zero!\n");
}
```

Convenient? Sure. Dangerous? Also yes.

Rust rejects that pattern:

```rust
let x = 5;

// ❌ Will not compile
if x {                  // error: expected `bool`, found integer
    println!("x is non-zero!");
}

// ✅ Be explicit
if x != 0 {
    println!("x is non-zero!");
}
```

Rust requires that the condition is explicitly a `bool`.

## 🛡️ Why Rust Does This

1. **Avoids subtle bugs**  
   In C, this compiles but is often accidental:

   ```c
   int x = 0;
   if (x = 5) {         // assignment, not comparison
       printf("x is 5\n");
   }
   ```

   By forcing boolean expressions, Rust eliminates this entire class of bugs.

2. **Strong type guarantees**  
   In Rust, if a value is an `i32`, it’s a number — not a boolean. Silent coercions weaken the type system and make intent ambiguous.

3. **Readable, intentional code**  
   `if x != 0` communicates intent better than `if x`. Less guessing for future readers (including you).

## ⚖️ Philosophy Contrast

- **C/C++**: Flexibility and minimal restrictions → treat many values as truthy/falsy.  
- **Java & Rust**: Safety and clarity → only `bool` is allowed in conditionals.

Rust’s approach fits its mission: *safe systems programming without sacrificing performance*.

## ✅ Takeaway

Rust might feel strict at first, but that strictness saves you from hidden pitfalls and makes your code clearer. The next time the compiler refuses a non-boolean `if` condition, remember — it’s doing you a favor. 🦀✨
