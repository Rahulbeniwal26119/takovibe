ORM is one of the great things that comes with Django. It frees us from writing complex, time‑consuming, and vulnerable raw SQL queries. So let’s find some ways I use at work to speed things up.

We’ll use these three models to understand the ideas:

```python
# models.py
from django.db import models

class Country(models.Model):
    name = models.CharField(max_length=50)
    population = models.PositiveIntegerField()

    def __str__(self):
        return self.name

class State(models.Model):
    name = models.CharField(max_length=50)
    country = models.ForeignKey(Country, on_delete=models.CASCADE)

    def __str__(self):
        return self.name

class City(models.Model):
    name = models.CharField(max_length=50)
    state = models.ForeignKey(State, on_delete=models.CASCADE)

    def __str__(self):
        return self.name
```

## 1) Utilize `values` and `values_list`

Consider: I want all country names from `Country`. One way is:

```python
Country.objects.all()
```

This is similar to:

```sql
SELECT * FROM country;
```

But this retrieves **all** fields. Time will grow as the number of fields grows. A better alternative:

```python
Country.objects.values_list("name", flat=True)
```

Which is similar to:

```sql
SELECT name FROM country;
```

**Difference between `values` and `values_list`:**

- `values()` returns a `QuerySet` of dicts where each dict represents a row. Dict keys are field names; values are the stored values.
- `values_list()` returns a list of tuples (or a flat list if `flat=True` and a single field is requested).

**Example:**

```python
list(Country.objects.values_list("name", flat=True))
# ["Country A", "Country B", "Country C"]
```

## 2) Use `select_related` and `prefetch_related`

These methods control how related objects are retrieved.

- `select_related` retrieves related objects in a **single query** using SQL joins (good for FK/OneToOne).
- `prefetch_related` performs **separate queries** and joins in Python (good for reverse FK/ManyToMany and to avoid N+1 across collections).

### Without optimizations

```python
c = City.objects.first()
```

```sql
SELECT "core_city"."id", "core_city"."name", "core_city"."state_id"
FROM "core_city"
ORDER BY "core_city"."id" ASC
LIMIT 1;
```

Accessing related objects fires more queries:

```python
c.state
```

```sql
SELECT "core_state"."id", "core_state"."name", "core_state"."country_id"
FROM "core_state"
WHERE "core_state"."id" = 1
LIMIT 1;
```

```python
c.state.country
```

```sql
SELECT "core_country"."id", "core_country"."name", "core_country"."population"
FROM "core_country"
WHERE "core_country"."id" = 1
LIMIT 1;
```

### With `select_related`

```python
c = City.objects.select_related("state", "state__country").first()
```

```sql
SELECT
  "core_city"."id", "core_city"."name", "core_city"."state_id",
  "core_state"."id", "core_state"."name", "core_state"."country_id",
  "core_country"."id", "core_country"."name", "core_country"."population"
FROM "core_city"
INNER JOIN "core_state" ON ("core_city"."state_id" = "core_state"."id")
INNER JOIN "core_country" ON ("core_state"."country_id" = "core_country"."id")
ORDER BY "core_city"."id" ASC
LIMIT 1;
```

```python
c.state.country  # <Country: India>
```

You can also project joined fields directly:

```python
City.objects.values_list("name", "state__name", "state__country__name")
```

### With `prefetch_related`

```python
c = City.objects.prefetch_related("state", "state__country").first()
```

This will run three small queries up front (city, state, country) and cache them, which shines when iterating over many cities.

Consider building a city→country map across many rows:

```python
# Anti-pattern (N+1 queries)
city_country_map = {}
for city in City.objects.all():
    city_country_map[city.name] = city.state.country.name
```

Use `prefetch_related` to cap DB hits:

```python
city_country_map = {}
for city in City.objects.prefetch_related("state", "state__country"):
    city_country_map[city.name] = city.state.country.name
# 😎 Only ~3 queries regardless of number of cities (for this relation set)
```

**When to use what**

- Use **`select_related`** when:
  - You have one-to-one or many-to-one (e.g., `ForeignKey`).
  - You know you’ll access the related object’s fields for most results.
- Use **`prefetch_related`** when:
  - You have many-to-many or one-to-many, or you’re iterating a collection.
  - You want to avoid the N+1 problem across many rows.

## 3) Add indexes to frequently accessed fields

Indexing creates a data structure to locate rows efficiently.

```python
class City(models.Model):
    name = models.CharField(max_length=50, db_index=True)
    state = models.ForeignKey(State, on_delete=models.CASCADE)

    def __str__(self):
        return self.name
```

You can add multi-column indexes too—just be mindful that **too many indexes** can slow writes.

```sql
CREATE INDEX "core_city_state_id_9aa9e056" ON "core_city" ("state_id");
```

# Let’s extend our example further for more Django ORM tricks

We’ll extend the models slightly for examples:

```python
# models.py
from django.db import models

class Country(models.Model):
    name = models.CharField(max_length=50)
    population = models.PositiveIntegerField()

    def __str__(self):
        return self.name

class State(models.Model):
    name = models.CharField(max_length=50)
    country = models.ForeignKey(Country, on_delete=models.CASCADE)
    population_factor = models.FloatField(default=1)

    def __str__(self):
        return self.name

class City(models.Model):
    name = models.CharField(max_length=50, db_index=True)
    state = models.ForeignKey(State, on_delete=models.CASCADE)
    population_factor = models.FloatField(default=1)

    def __str__(self):
        return self.name
```

## 1) Use `annotate()` and `aggregate()`

Django can perform calculations in the database instead of post‑processing in Python.

**`annotate()`** adds calculated fields to each row:

```python
from django.db.models import F

res = (
    City.objects
    .annotate(
        city=F("name"),
        city_state=F("state__name"),
        country=F("state__country__name"),
        population=F("population_factor") * F("state__population_factor") * F("state__country__population"),
    )
    .values("name", "city_state", "country", "population")
)

# <QuerySet [
#   {'name': 'Bangalore', 'city_state': 'Karnataka', 'country': 'India', 'population': 40000000.00000001},
#   {'name': 'Mysore',     'city_state': 'Karnataka', 'country': 'India', 'population': 40000000.00000001},
#   {'name': 'Chennai',    'city_state': 'Tamil Nadu','country': 'India', 'population': 40000000.00000001},
# ]>
```

**`aggregate()`** computes values across the queryset:

```python
from django.db.models import Min, Max, Sum, Avg, ExpressionWrapper, FloatField, F

City.objects.annotate(
    population=ExpressionWrapper(
        F("population_factor") * F("state__population_factor") * F("state__country__population"),
        output_field=FloatField(),
    )
).aggregate(
    max_population=Max("population"),
    min_population=Min("population"),
    avg_population=Avg("population"),
    sum_population=Sum("population"),
)

# {
#   'max_population': 40000000.00000001,
#   'min_population': 40000000.00000001,
#   'avg_population': 40000000.00000001,
#   'sum_population': 120000000.00000003,
# }
```

## 2) Use `exists()` and `count()` instead of built‑in `len()`

- `exists()` → check if any record matches a condition.
- `count()` → let the DB compute counts.

```python
State.objects.filter(country__name="India").count()
# vs
len(State.objects.filter(country__name="India"))  # expands the queryset in Python
```

The results are the same, but `count()` is more efficient and memory‑friendly for large result sets.

```python
State.objects.filter(country__name="India").exists()
# True
```

## 3) Use `defer()` and `only()`

`values()` returns dicts; `defer()`/`only()` return model instances with partial fields loaded. Deferred fields are fetched **lazily** when accessed.

**`only()`**: load only specific fields eagerly; others are deferred.

```python
res = Country.objects.only("id")
result = res[0]
# SQL: SELECT "core_country"."id" FROM "core_country" LIMIT 1

result.id      # no extra query
result.name    # triggers a query for deferred field
# SQL: SELECT "core_country"."id", "core_country"."name" FROM "core_country" WHERE "core_country"."id" = 1 LIMIT 1
```

**`defer()`**: eagerly load everything **except** specified fields.

```python
res = Country.objects.defer("name")
result = res[0]
# SQL: SELECT "core_country"."id", "core_country"."population" FROM "core_country" LIMIT 1

result.population  # no extra query
result.name        # triggers fetch of deferred field
# SQL: SELECT "core_country"."id", "core_country"."name" FROM "core_country" WHERE "core_country"."id" = 1 LIMIT 1
```

> TL;DR: `only()` loads the listed fields now; `defer()` loads the listed fields later.

## 4) Raw SQL or database‑specific queries (use sparingly)

Caution: Raw SQL reduces portability and can hurt maintainability—prefer the ORM unless you **must** drop down.

```python
from django.db import connection

query = "SELECT * FROM core_country;"

with connection.cursor() as cursor:
    res = cursor.execute(query)
    columns = [col[0] for col in res.description]
    rows = res.fetchall()
    result = [dict(zip(columns, row)) for row in rows]
    print(result)

# Output -> [
#   {'id': 1, 'name': 'India', 'population': 1000000000},
#   {'id': 2, 'name': 'India', 'population': 1000000000},
# ]
```
