Today, I would like to discuss one more popular injection attack, which is Command Injection. Easy to understand, but the consequences are fatal.

# What is Command Injection
Command injection happens when a vulnerable application (Can be a web app or any client-facing app) passes unsafe user input to a system shell, allowing any malicious OS command to run with the app's privileges. The higher the privileges your app has more it will be damaged.

## Why it happens (the mental model)
* Code **concatenates** user input into a command string. The code **invokes a shell** (`/bin/sh`, `bash`, `cmd.exe`) or a function that does so by default.
* The result runs with **your app’s permissions** (Mostly powerful to do enough damage)

## Code Examples

### Python: Bad Code
```python
import os
def list_dir(user_input):
    cmd = "ls " + user_input
    print("Running:", cmd)
    os.system(cmd)

list_dir("file; echo hello i can also pass rm command")

# OUTPUT
# Running: ls file; echo hello i can also pass rm command
# ls: cannot access 'file': No such file or directory
# hello i can also pass rm command
```

### Python: Fix

```python
import subprocess
def list_dir_safe(path):
    subprocess.run(["ls", path], check=True)

list_dir_safe("ls; echo i can pass rm command")
# ls: cannot access 'ls; echo i can pass rm command': No such file or directory
```

> Why fix works: `subprocess.run` run command directly without shell and pass argument directly to command  but os.system does.

# Fixes for Command Injection
## 1. Avoid the shell entirely when possible

If you have a choice to implement a functionality using a language API, then please use that. For listing files, you can use `os.listdir`

```python
import os
def list_dir_python(path):
    print(os.listdir(path))
```

## 2. If you must use a shell, escape properly
Escaping can be tricky and error-prone. You have to go out and search for a language guide to know how you do it properly. Please don't take any chances.

I am explaining how you can do it in Python.

```python
import subprocess, shlex

def list_dir_escaped(path):
    safe = shlex.quote(path)
    subprocess.run("ls " + safe, shell=True)

list_dir_escaped("; echo hello")
# ls: cannot access '; echo hello': No such file or directory
```

## 3. Run with least privilege
I would recommend never reaching this step; better use the language API or a non-shell, but if its use is inevitable and run with least privilege. Even if an injection occurs, limit damage by running services as unprivileged users, using containers, SELinux/AppArmor, or sandboxing.

# Detecting & testing for command injection
* **Code review:** search for `system`, `exec`, `popen`, `shell=True`, `child_process.exec`, `os.system`. GitHub already has code scanning functionality to report potential issues, but it is limited to organizations only.
* **Static analysis**: use tools (e.g., Bandit for Python, ESLint plugins, commercial SAST) to flag risky uses. I will cover bandit in the future.
* **Dynamic tests / DAST:** scanners like OWASP ZAP, Burp, or targeted tests can spot injection paths.

# Practical Checklist to Escape from Command Injection
* Replace `exec`/`system` with argument-array calls (`subprocess.run([...])`).
* If you must use a shell, use strict escaping and understand risks.
* Prefer native APIs over shell commands.
* Validate input with whitelists; avoid blacklists
* Limit process/user privileges and use sandboxing.
* Add SAST/DAST checks in CI
